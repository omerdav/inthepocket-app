### R1 — Behaviour before the fix

All three cases were established by running the exploratory version of the spec
and then, once assertions were added, watching them fail:

| Case | Before |
|---|---|
| Disconnect mid-drill | Drill ran to completion against silence. No result appeared at all — the screen returned to Start with no explanation. |
| Tab hidden mid-drill | Drill continued and graded the silence. `data-error` was empty. |
| Kit connected after load | Already worked once `isKitConnected` existed. |

### The three bugs that stopped the design working

**1. The result was set but never rendered.** `DrillSession.tsx:339` renders the
result screen only when `phase === 'complete'`, and `_abortResult` emitted
`'idle'` for every abort. So a drummer's kit died mid-drill, a correct result
object was created, and the screen went quietly back to Start. Fixed by
emitting `'idle'` only for `'cancelled'` — where the drummer chose to stop and
there is nothing to report — and `'complete'` for everything that happened *to*
them.

**2. `_awaitFirstBeat` sat outside the try.** "Metronome did not start" escaped
the new handling entirely and fell through to DrillSession's backstop, losing
its specific message. Moved inside.

**3. The visibility check could not be simulated.** The code tested
`document.hidden`, which is a derived getter; a test overriding
`visibilityState` does not change it. Switched to
`document.visibilityState === 'hidden'` — the canonical property, and the one a
test can simulate without overriding two getters that a real browser changes
together.

### A regression this introduced, and why the backstop stays

The interrupted work removed DrillSession's catch entirely, with the comment
*"DrillRunner handles expected stalls"*. It does not handle all of them:
`run()` still throws when audio refuses to unlock, when the engine fails to
initialise, and for anything unforeseen. Removing the catch broke both tests
guarding T-017 — each mocks `run()` to reject outright, which is exactly the
shape of failure the backstop exists for.

It is restored, and commented as a backstop rather than duplication.

### Notes for review — P-1

Nothing here explains P-1. The tab-hidden path is now handled, so if a wedged
clock were ever a backgrounded tab, it would present as "Drill Paused" rather
than the current silent stall — **which means a future P-1 sighting that still
says "Audio System Interrupted" has ruled backgrounding out.** That is a small
narrowing, not a cause.

One observation worth recording: `_sleepUntilAudioTime` declares the clock
stalled after 2000ms of no advance. The measured wedge advances exactly one
512-frame quantum and then stops dead, so it trips this reliably — but a clock
running slowly rather than stopping would not trip it at all, and nothing else
would notice.
