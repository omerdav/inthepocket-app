# T-055 — Strip the `?dev=1` harness

**Finished by the owner** after the delegated attempt was handed back unbuilt and
unreported. The delegated work is preserved as the first commit on this branch;
what the owner added is recorded separately below so the split is visible.

### Commit

- `547f758` — the delegated change, applied unmodified onto a real branch off
  `master`. It had been committed **directly onto `master` inside a filesystem
  copy of the repository**, which is why it never reached anyone.
- Owner commit — the nine build errors, the G2 baseline, an orphaned snapshot,
  and this report.

### What the delegated commit got right

- The harness is genuinely gone. `dev=1`, `IS_DEV_VIEW`, `dummySequence` and
  `PAD_MAP` return **zero** matches across `src/` and `e2e/`. 332 deletions.
- **P-18 fixed** — G5's `return true` fallback is removed, so a canvas that never
  drew no longer passes as an alignment success.
- **P-16 fixed** — the App-level `GrooveCircle`, its mount, its
  `isSettingsMenuOpen` effect and the `worker.onmessage` handler that fed it are
  all gone. They were unreachable outside the harness.
- **R4 done** — `no-e2e.test.ts` now enumerates the P-17 surface, so a new hook
  fails the guard instead of joining it silently.
- 111 lines of dev-only CSS removed, and no product class went with them.

### What was broken, and is now fixed

**`npm run build` failed with nine errors** — every one an unused import left
behind by the deletion (`MIDI_NOTE`, `HitEvent`, `GrooveCircle`,
`ScoringWorkerResultMessage`, `effect`, the whole `RhythmGrid` line, and
`dismissFirstRun` in three specs). The task file warned about this failure mode
in bold. **No report accompanied the commit**, so nothing claimed the build had
been run — and it had not.

**G2's pixel baseline was stale.** It was captured against the harness's canvas
(321px, 120 BPM) and the product path uses `DrillSession`'s (320px, the drill's
real 80 BPM). Regenerated and **inspected by eye, not merely accepted**: the new
image is the Groove Circle with a green perfect-hit ring and four beat markers,
which is what a perfect hit should look like.

**An orphaned snapshot** — `g2-perfect-glow-chromium-win32.png`, dead since the
Playwright project was renamed from `chromium` to `product` in July — deleted.

### Mutation check

Neither guard came with a mutation check, so both were checked here.

- **R4 guard.** Appended `(window as any).__someNewHook` to a product file:
  `no-e2e.test.ts` **failed** with `unlisted scaffolding hook`. Restored, green.
- **The quickmenu migration**, which replaces two harness buttons with a
  `DRILL_PHASE_EVENT` dispatch. Changed the dispatched phase to
  `THIS_IS_NOT_A_PHASE`: the test **failed** on `not.toBeAttached()`. Restored,
  green. The assertion is load-bearing — `DrillSession.tsx:164` listens.

### Notes for review

**A second agent reported this task impossible.** Its report argued R1 could not
be done without weakening the tests, for three reasons: `enterApp` dismisses the
overlays `first-run` needs, the Groove Circle ignores hits while the session is
idle, and the QuickMenu is not visible on load. **All three are answered by the
commit that shipped** — the circle problem by starting the drill before
dispatching hits, which is what the second agent had not tried. The block was
honest and the reasoning was specific; it was simply one step short.

**Not fixed here, and deliberately so:** the P-17 surface is frozen, not removed.
`throneview.spec.ts` gets its colour assertions through `itp-simulate-hit` and
`itp-force-render`, and replacing that coverage is its own task. The guard now
makes the surface visible and bounded, which it was not before.

**One thing worth an owner decision:** the header still ships the tagline
`PRO VIRTUAL DRUMMER`. It is the only string from the old dev-facing chrome left
in the bundle. It is product markup rather than scaffolding, so it is out of
scope here — but it reads oddly on an app for drummers playing real kits.
