# Fixes for T-017: Intermittent Drill Hang

## R2: Determine if engine error is being swallowed (PRIMARY)
Yes, it was. When `DrillRunner` threw an error (e.g., "AudioContext clock is not advancing"), the exception was caught by `DrillSession`. However, `DrillSession` incorrectly assumed *all* errors were due to the browser blocking audio, and silently set the phase to `idle` while showing the generic "Audio is blocked" overlay.

## R3: Make failure legible
To fix this, `DrillSession.tsx` was updated to differentiate between actual audio locking and engine stalling. When an engine stall occurs, it now returns an explicit failing `DrillResult`:
* **UI**: The drummer sees a failure screen with "Audio System Interrupted: The drill could not complete because the browser audio engine stalled or failed to start." The verdict headline now shows "Interrupted" instead of "Not yet", so the drummer knows they didn't fail.
* **Audit**: The test receives `Passed=false` with the diagnosis "Audio System Interrupted". I added an audit guard in `drill-audit.spec.ts` that asserts the diagnosis must NOT contain "Audio System Interrupted". This ensures a stalled drill cannot silently pass the rushing criteria.

## Check Candidate Explanation for Observation B
The candidate explanation that "B is racy by construction because it uses a timestamp from the past" is **incorrect**.
Looking closely at `GrooveCircle.ts`, the hit alpha decay does **not** begin at the hit timestamp (`start`). When a hit is registered, `this._lastHitTimeMs` is set to `performance.now()`, which is the exact moment the test script calls `registerHit` (via `__virtualDrummer.hit`). 
Therefore, the elapsed time since `start` is completely irrelevant to the alpha decay block.

**Conclusion:** Both Observation A (silent failure) and Observation B (GrooveCircle not rendering) are perfectly explained by the same root cause. The audio engine clock stalled, causing `DrillRunner` to throw. `DrillSession` swallowed this error and immediately set `phase = 'idle'`.
* For **A**, this wiped the result, causing the audit to silently fail.
* For **B**, moving to `idle` triggered `GrooveCircle.stop()`, which cancelled the `requestAnimationFrame` loop, explaining why `__E2E_LAST_HIT_COLOR__` was never updated.

Both are now fully mitigated by the legibility fix. A stalled test will now visibly fail and crash the audit correctly, rather than hanging.
