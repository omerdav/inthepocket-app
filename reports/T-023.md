# Task T-023: One pedal chick enters the scoring path as three hits

## R1 Finding (Before any change)
By writing a test `R1: one open->close cycle records EVERY emitted event` in `hihat-tracker.test.ts`, I observed exactly what happens in a pedal closure sequence:
```
Emitted events:
Event 1: hihat-open
Event 2: hihat-closed
Event 3: hihat-chick
```
Because `src/audio/midi.ts` previously mapped all three events to `_dispatchHit` with their respective MIDI notes, one physical press by the drummer resulted in exactly three simulated hits in the application's processing stream.

## User-Reachable Consequence
A drummer playing a hi-hat chick would incorrectly see their hit count massively inflated (e.g. 28 recorded hits for 12 actual notes), eroding trust in the scoring system since they know exactly how many notes they played.

## Per-File Change List
* `src/audio/__tests__/hihat-tracker.test.ts`: Added an explicit test to drive one open-to-close cycle to capture the `HiHatStateTracker` emissions to prove the three-event pattern.
* `src/audio/midi.ts`: Modified the `onEvent` callback from `HiHatStateTracker` so that only `hihat-chick` (the actual percussive strike) is passed to `_dispatchHit`. Continuous pedal state transitions (`hihat-open`, `hihat-closed`) are dropped from the hit stream.
