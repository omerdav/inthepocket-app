## Task: T-034 — P-5 does not cost one test, it costs eight

### What I changed
- `e2e/drill-session.spec.ts`: Replaced the hardcoded 50ms `setTimeout` in the Groove Circle visibility test with Playwright's `expect().toHaveAttribute()`. The test failed intermittently (H-A mechanism) because `requestAnimationFrame` isn't guaranteed to fire within a strict 50ms window (e.g. if the tab is backgrounded or Playwright throttles rendering). A test asserting on a frame being painted in a strict 50ms setTimeout window without polling is a test bug.
- `e2e/drill-session.spec.ts`: Removed `test.describe.configure({ mode: 'serial' })`. The `serial` mode causes a single failure to abort the rest of the file (the "seven tests did not run" cascade). The concurrency concerns it meant to address ("Concurrent browser contexts starve the audio thread") are already handled globally by `fullyParallel: false` and `workers: 1` in `playwright.config.ts`. Tests now run sequentially but independently, preventing the cascade.

### User-reachable path
The Groove Circle test asserts on the main playing screen visual feedback. A user reaches this by selecting any drill (e.g. from the drill selection screen) and pressing "Start". The visual hit feedback is visible during the `playing` phase on the `GrooveCircle` component.
