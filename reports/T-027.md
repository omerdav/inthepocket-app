## Task: T-027 — Make the Groove Circle's live feedback tell the truth

### What I changed
- `src/components/drills/DrillSession.tsx`: Replaced hardcoded delta calculation with logic that measures hit timing directly against the `unit.sequence` targets (R1) and categorizes timing using the drill's `timingWindowMs` (R3).
- `src/components/canvas/GrooveCircle.ts`: Implemented a 30ms flush timer in `registerHit` to buffer hits and emit only the worst hit (by score and delta magnitude) for Blind Mode and visualization (R2). Also added a `noFlush` parameter to the E2E simulation hook to allow testing the coalescer.
- `e2e/drill-session.spec.ts`: Modified the "blind mode fades out" test to trigger a genuinely late hit via the `vd.hit` Virtual Drummer path instead of injecting it, and added an assertion that the resulting hit is non-green (R4).
- `e2e/throneview.spec.ts`: Added test `G5 - Coalescing Simultaneous Hits (R2)` to verify that when simultaneous hits occur, the worst one is kept.

### User-reachable path
Start the application, select any drill (e.g., "Quarter Note Check"), wait for the count-in to finish, and start playing on a connected MIDI drum kit (or using the virtual drummer in tests). The visual feedback (Groove Circle color and Tuner Pulse) and the Blind Mode fade mechanics directly exercise these changes.

### Requirements
- [x] R1 — Measure against drill's targets: Used `correlator` in `DrillSession.tsx` to map hit timestamps and sequence target times to the audio clock, finding the closest sequence target and passing that delta to `GrooveCircle`.
- [x] R2 — Coalesce simultaneous hits: Added a `_flushTimer` in `GrooveCircle.ts` that buffers incoming hits for 30ms. It keeps the hit with the worst score or, on a tie, the highest absolute delta.
- [x] R3 — Colour thresholds from the drill's band: Extracted `categoriseTiming` from `scoring.types.ts` and fed the result of `categoriseTiming(deltaMs, unit.passCriteria.timingWindowMs)` to `GrooveCircle`.
- [x] R4 — Prove a late hit reads non-green: Modified the blind mode test in `e2e/drill-session.spec.ts` to use `vd.hit` with an offset of 60ms past the target beat to trigger a late hit visually and functionally.
- [x] R5 — Answer explicitly whether the existing fade test still passes, and why: Yes, the existing fade test (G1 in `throneview.spec.ts`) still passes. It injects hits directly into `GrooveCircle` using the `__E2E_SIMULATE_HIT__` hook. Since this hook bypasses the MIDI engine and sequence correlation entirely, the new delta logic in `DrillSession` does not break it. Also, because the hook simulates hits serially across animation frames, the new coalescer handles them seamlessly.

### Notes for review
- E2E test `__E2E_SIMULATE_HIT__` immediately calls `this._flushHits()`. In order to effectively write a coalescing test (G5), I added an optional `noFlush` parameter to prevent this hook from preemptively flushing hits.
- To execute R4 reliably without injecting a fake hit, I targeted `start + 12 * spacing` and calculated `intendedHitTime = lateTargetPerfMs + 60` before pushing it down the virtual drummer's pipe.
