# T-022: One missing hit makes the app tell a drummer they rushed everything

## 1. Defect Analysis

**Register**: P-6

The `ScoringWorker.ts` matched hits to targets using a greedy algorithm (`O(T * H)` where `T` is targets and `H` is hits, but doing it in target-order purely locally). It searched for the closest unused hit up to a hard ceiling of `maxDistance`.

This greedy strategy completely fails to preserve hit ordering. A single missed note, a spurious note, or an off-by-one hardware delay causes a cascading misalignment:
1. Target `i` takes hit `i+1` (which is technically closest in the forward direction when hit `i` is missing).
2. Target `i+1` takes hit `i+2`.
3. Every subsequent target consumes the hit meant for the next target.
As a result, a drummer gets a diagnosis like "You're rushing on beats 4, 1, 2 and 3" when they actually just missed beat 4 and played everything else perfectly.

## 2. Root Cause of `hh-indep-1` Regression in Initial DP Approach

The sequence alignment approach (Needleman-Wunsch / Damerau-Levenshtein hybrid) successfully prevents the cascading error by globally optimizing the assignment order (penalizing target skips and hit skips). 

However, when initially deployed, it regressed real hi-hat drills (`hh-indep-1` and `hh-indep-2`). The root cause was that `matchCost` heavily favored absolute timing precision (`absDelta`) over instrument zone accuracy. The penalty for matching a target to the wrong zone was only `0.1ms`. 

Because a hi-hat pattern offers multiple hits per time window across different zones (e.g., cymbal vs kick drum), the DP would happily match a Kick target to a Hi-Hat hit that was `0.1ms` closer in time, trading zone accuracy for an infinitesimal gain in timing score. This generated massive spurious offsets for targets matched to the wrong instrument hits, ruining the final grade.

By introducing a `ZONE_MISMATCH_PENALTY` of `500` (equivalent to a 500ms timing error) and a `MISS_TARGET_PENALTY` of `10000`, the DP correctly prioritizes zone accuracy first and absolute timing second.

## 3. Changes Made

### `src/workers/ScoringWorker.ts`
- Removed the local greedy `for (j)` target search loop.
- Implemented a global `$O(T \times H)$` Dynamic Programming sequence alignment (Needleman-Wunsch / Damerau-Levenshtein variant).
- Allowed transpositions (cost = `absDelta` for crossed pairs) to handle simultaneous hits arriving out-of-order from hardware without breaking the sequential chain.
- Assigned semantic penalty weights:
  - `MISS_TARGET_PENALTY = 10000`
  - `SKIP_HIT_PENALTY = 0` (spurious hits are harmless and must not warp the DP path)
  - `ZONE_MISMATCH_PENALTY = 500`

### `src/workers/__tests__/scoring.test.ts`
- Updated R1 unit tests to reflect realistic offsets. An unmatched target is logged with `offset === 0` but `categories[i] === MISS` and `struckZones[i] === -1`. The tests now explicitly assert against `categories` and `struckZones`.

## 5. Notes on P-9

It was observed that `hh-indep-*` drills receive an inflated hit count (e.g., `24/8`, representing 24 registered hits for an 8-hit drill). This is because every hi-hat chick triggers simultaneous spurious hits on the Crash, Ride, and Cymbal zones, indicating poor instrument isolation. 
This is out of scope for T-022, but the DP algorithm was designed to effectively discard these extra hits through a `SKIP_HIT_PENALTY` of `0` and a high `ZONE_MISMATCH_PENALTY`. T-022 relies on this hardware defect being fixed separately under P-9.
