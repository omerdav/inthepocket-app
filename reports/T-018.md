## Task: T-018 — The audit's rushing offset sits on a band boundary

### Expected outcome (written before the run)

- Every PERFECT run passes (offset 0).
- Every ACCEPTABLE run passes (early offset inside the GREEN band).
- Every RUSHING run FAILS (early offset outside the GREEN band) — including
  dynamics-gate-drill-1, dynamics-gate-drill-2, and hh-indep-1, which passed
  under the old fixed −40ms offset.

### Offset derivation

`categoriseTiming` treats `absDelta <= timingWindowMs` as GREEN, so the band
boundary **is** `timingWindowMs`.

```ts
const BOUNDARY_EXCLUSION_MS = 5; // R3
const CLEARANCE_MS = 10;         // must be > BOUNDARY_EXCLUSION_MS

perfect:     0
acceptable:  timingWindowMs - CLEARANCE_MS   // inside GREEN
rushing:     timingWindowMs + CLEARANCE_MS   // outside GREEN
```

**Why 10ms:** R3 forbids any run within ±5ms of the boundary. 10ms clears that
exclusion zone with the same headroom the original defect lacked, and absorbs
the 1–2ms of scheduling jitter that made a hit exactly on Developing's ±40ms
edge nondeterministic. Offsets are derived from each drill's
`passCriteria.timingWindowMs` — not tabulated.
